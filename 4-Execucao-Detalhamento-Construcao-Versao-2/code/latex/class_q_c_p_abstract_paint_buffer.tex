\doxysubsection{Detailed Description}
The abstract base class for paint buffers, which define the rendering backend. 

This abstract base class defines the basic interface that a paint buffer needs to provide in order to be usable by \doxylink{class_q_custom_plot}{QCustom\+Plot}.

A paint buffer manages both a surface to draw onto, and the matching paint device. The size of the surface can be changed via \doxylink{class_q_c_p_abstract_paint_buffer_a8b68c3cd36533f1a4a23b5ce8cd66f01}{set\+Size}. External classes (\doxylink{class_q_custom_plot}{QCustom\+Plot} and \doxylink{class_q_c_p_layer}{QCPLayer}) request a painter via \doxylink{class_q_c_p_abstract_paint_buffer_ab1329e5e2cfc44a7cef1b5e9b6fab20d}{start\+Painting} and then perform the draw calls. Once the painting is complete, \doxylink{class_q_c_p_abstract_paint_buffer_a996577a718aecb3b9b5351fab797a062}{done\+Painting} is called, so the paint buffer implementation can do clean up if necessary. Before rendering a frame, each paint buffer is usually filled with a color using \doxylink{class_q_c_p_abstract_paint_buffer_a7fc69e37c2a8232e8b2eb8b5853aae4c}{clear} (usually the color is {\ttfamily Qt::\+transparent}), to remove the contents of the previous frame.

The simplest paint buffer implementation is \doxylink{class_q_c_p_paint_buffer_pixmap}{QCPPaint\+Buffer\+Pixmap} which allows regular software rendering via the raster engine. Hardware accelerated rendering via pixel buffers and frame buffer objects is provided by QCPPaint\+Buffer\+Gl\+Pbuffer and QCPPaint\+Buffer\+Gl\+Fbo. They are used automatically if \doxylink{class_q_custom_plot_a7db1adc09016329f3aef7c60da935789}{QCustom\+Plot::\+set\+Open\+Gl} is enabled.
