\doxysubsection{Detailed Description}
The base class tick generator used by \doxylink{class_q_c_p_axis}{QCPAxis} to create tick positions and tick labels. 

Each \doxylink{class_q_c_p_axis}{QCPAxis} has an internal \doxylink{class_q_c_p_axis_ticker}{QCPAxis\+Ticker} (or a subclass) in order to generate tick positions and tick labels for the current axis range. The ticker of an axis can be set via \doxylink{class_q_c_p_axis_a4ee03fcd2c74d05cd1a419b9af5cfbdc}{QCPAxis::\+set\+Ticker}. Since that method takes a {\ttfamily QShared\+Pointer$<$\+QCPAxis\+Ticker$>$}, multiple axes can share the same ticker instance.

This base class generates normal tick coordinates and numeric labels for linear axes. It picks a reasonable tick step (the separation between ticks) which results in readable tick labels. The number of ticks that should be approximately generated can be set via \doxylink{class_q_c_p_axis_ticker_a47752abba8293e6dc18491501ae34008}{set\+Tick\+Count}. Depending on the current tick step strategy (\doxylink{class_q_c_p_axis_ticker_a73b1d847c1a12159af6bfda4ebebe7d5}{set\+Tick\+Step\+Strategy}), the algorithm either sacrifices readability to better match the specified tick count (\doxylink{class_q_c_p_axis_ticker_ab6d2f9d9477821623ac9bc4b21ddf49aa770312b6b9b0c64a37ceeba96e0cd7f2}{QCPAxis\+Ticker::\+tss\+Meet\+Tick\+Count}) or relaxes the tick count in favor of better tick steps (\doxylink{class_q_c_p_axis_ticker_ab6d2f9d9477821623ac9bc4b21ddf49aa9002aa2fd5633ab5556c71a26fed63a8}{QCPAxis\+Ticker::\+tss\+Readability}), which is the default.

Creating own axis tickers can be achieved very easily by sublassing \doxylink{class_q_c_p_axis_ticker}{QCPAxis\+Ticker} and reimplementing some or all of the available virtual methods.

In the simplest case you might wish to just generate different tick steps than the other tickers, so you only reimplement the method \doxylink{class_q_c_p_axis_ticker_a910d69bcec2de37e92d8d4e1ecf201e2}{get\+Tick\+Step}. If you additionally want control over the string that will be shown as tick label, reimplement \doxylink{class_q_c_p_axis_ticker_a8201eb4aa8be192bf786b126eb5ee089}{get\+Tick\+Label}.

If you wish to have complete control, you can generate the tick vectors and tick label vectors yourself by reimplementing \doxylink{class_q_c_p_axis_ticker_af4645a824c7bd2ca8fc7e86ebf9055bd}{create\+Tick\+Vector} and \doxylink{class_q_c_p_axis_ticker_a804050e408f37a0b9770c6654ebe6aa7}{create\+Label\+Vector}. The default implementations use the previously mentioned virtual methods \doxylink{class_q_c_p_axis_ticker_a910d69bcec2de37e92d8d4e1ecf201e2}{get\+Tick\+Step} and \doxylink{class_q_c_p_axis_ticker_a8201eb4aa8be192bf786b126eb5ee089}{get\+Tick\+Label}, but your reimplementations don\textquotesingle{}t necessarily need to do so. For example in the case of unequal tick steps, the method \doxylink{class_q_c_p_axis_ticker_a910d69bcec2de37e92d8d4e1ecf201e2}{get\+Tick\+Step} loses its usefulness and can be ignored.

The sub tick count between major ticks can be controlled with \doxylink{class_q_c_p_axis_ticker_a4ccc403ced7a1457ce6ba293509933c8}{get\+Sub\+Tick\+Count}. Full sub tick placement control is obtained by reimplementing \doxylink{class_q_c_p_axis_ticker_a9a6435723fa0bd366d1ea4c2cff7c33f}{create\+Sub\+Tick\+Vector}.

See the documentation of all these virtual methods in \doxylink{class_q_c_p_axis_ticker}{QCPAxis\+Ticker} for detailed information about the parameters and expected return values.

void QCPAxis\+Ticker::\+generate (\begin{DoxyParamCaption}\item[{const \doxymbox{\hyperlink{class_q_c_p_range}{QCPRange}} \&}]{range}{, }\item[{const QLocale \&}]{locale}{, }\item[{QChar}]{format\+Char}{, }\item[{int}]{precision}{, }\item[{QVector$<$ double $>$ \&}]{ticks}{, }\item[{QVector$<$ double $>$ \texorpdfstring{$\ast$}{*}}]{sub\+Ticks}{, }\item[{QVector$<$ QString $>$ \texorpdfstring{$\ast$}{*}}]{tick\+Labels}{}\end{DoxyParamCaption})\hspace{0.3cm}{\ttfamily [virtual]}}

This is the method called by \doxylink{class_q_c_p_axis}{QCPAxis} in order to actually generate tick coordinates ({\itshape ticks}), tick label strings ({\itshape tick\+Labels}) and sub tick coordinates ({\itshape sub\+Ticks}).

The ticks are generated for the specified {\itshape range}. The generated labels typically follow the specified {\itshape locale}, {\itshape format\+Char} and number {\itshape precision}, however this might be different (or even irrelevant) for certain \doxylink{class_q_c_p_axis_ticker}{QCPAxis\+Ticker} subclasses.

The output parameter {\itshape ticks} is filled with the generated tick positions in axis coordinates. The output parameters {\itshape sub\+Ticks} and {\itshape tick\+Labels} are optional (set them to {\ttfamily nullptr} if not needed) and are respectively filled with sub tick coordinates, and tick label strings belonging to {\itshape ticks} by index.

void QCPAxis\+Ticker::\+set\+Tick\+Origin (\begin{DoxyParamCaption}\item[{double}]{origin}{}\end{DoxyParamCaption})}

Sets the mathematical coordinate (or "{}offset"{}) of the zeroth tick. This tick coordinate is just a concept and doesn\textquotesingle{}t need to be inside the currently visible axis range.

By default {\itshape origin} is zero, which for example yields ticks \{-\/5, 0, 5, 10, 15,...\} when the tick step is five. If {\itshape origin} is now set to 1 instead, the correspondingly generated ticks would be \{-\/4, 1, 6, 11, 16,...\}.
